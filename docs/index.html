What is NimDrake?

A transparent Nim binding for DuckDB.

DuckDB is an embedded OLAP database: it runs inside your process, no server needed, and is tuned for analytical SQL — large scans, aggregations, joins over CSV, Parquet, and Arrow input. NimDrake exposes it with a layered API: a high-level con.execute for day-to-day work, and a low-level Vector[kt] layer for streaming results.

The philosophy is zero-copy where it matters: your Nim code views DuckDB's own columnar buffers directly, so reading a million rows of int64 costs pointers, not per-row copies. Complex kinds (List, Struct, Map, Decimal, …) stay typed via zero-copy container views instead of falling back to opaque JSON.

Your first query

import nimdrake

let con = newDatabase().connect()

let r = con.execute("""
  SELECT i, i * i AS sq
  FROM generate_series(1, 5) AS t(i)
""")
echo r
┌───────────┬────────────┐ │ i │ sq │ ├───────────┼────────────┤ │ 1 │ 1 │ │ 2 │ 4 │ │ 3 │ 9 │ │ 4 │ 16 │ │ 5 │ 25 │ └───────────┴────────────┘

Read results as typed vectors

Iterate chunks and bind columns to strong Nim types — no copies, no object conversion.

Every QResult iterates over hidden chunks. Within a chunk, vector(i) exposes a typed, zero-copy view. Values are fetched through Nim's index operator and NULLs are checked with valid(i). Columns can be addressed by index or by name.

Typed access by column, with NULL handling

for chunk in r:
  let nums = chunk.vector(0).bindAs DuckType.BigInt
  let msgs = chunk.vector(1).bindAs DuckType.Varchar
  if nums.valid(0):          # NULL check
    echo nums[0], " ", msgs[0]
42 hello

Whole columns materialize instantly with toSeq: 

let vals = chunk.vector(0).bindAs(DuckType.BigInt).toSeq
echo vals   # @[1, 2, 3, 4, 5]

Prepared statements and query parameters

Bind tuples or named parameters; reuse the statement across executions.

Preparing once and re-executing is both faster and safer than string interpolation. NimDrake binds a plain Nim tuple positionally, so parameter types are checked by DuckDB, not by string surgery.

Insert with tuple binding

let stmt = con.newStatement("INSERT INTO people VALUES (?, ?, ?)")
con.executeMaterialized(stmt, (1, "Alice", true))
con.executeMaterialized(stmt, (2, "Bob", false))

let r = con.execute("SELECT * FROM people ORDER BY id")
echo r
┌────────────┬───────────────┬────────────────┐ │ id │ name │ active │ ├────────────┼───────────────┼────────────────┤ │ 1 │ Alice │ true │ │ 2 │ Bob │ false │ └────────────┴───────────────┴────────────────┘

Named parameters use $name syntax and report their index and expected type through the statement: 

let stmt = con.newStatement("SELECT CAST($val AS BIGINT)")
let idx = stmt.bindParameter("val")          # 1
echo idx
1

Stream results, don't buffer them

Chunked iteration keeps memory flat on terabyte-scale scans.

For large result sets, execute the statement in streaming mode and consume one chunk at a time. Iterating a million rows never materializes the whole thing.

Stream a million rows, count them

let stmt = con.newStatement(
  "SELECT i FROM generate_series(1, 1_000_000) AS t(i)")

var count = 0
for chunk in con.executeStreaming(stmt):
  let v = chunk.vector(0).bindAs DuckType.BigInt
  count += v.len

echo "Total rows: ", count
Total rows: 1000000

Pending results let you drive execution manually with step() for progress reporting or cancellation — see Query Execution in the cookbook.

Bulk insert with the Appender

The fastest path for loading large volumes of data.

Append row by row, then close

con.execute("CREATE TABLE logs (ts VARCHAR, level VARCHAR, msg VARCHAR)")

var appender = con.newAppender("logs")
for i in 0 ..< 100:
  appender.append("2024-01-01 00:00:00")
  appender.append("INFO")
  appender.append("Event " & $i)
  appender.endRow()
appender.close()

let r = con.execute("SELECT count(*)::BIGINT AS n FROM logs")
echo r
┌─────────────┐ │ n │ ├─────────────┤ │ 100 │ └─────────────┘

Pass none(T) to write SQL NULL, or bulk-insert a seq of rows at once with con.appendRows. See Bulk Insert with Appender.

Register Nim functions in the engine

Scalar, aggregate, and table functions — the engine calls your proc.

Write an ordinary Nim proc, register it, and call it from SQL. NULL inputs propagate to NULL outputs automatically.

A scalar function

proc multiply(a, b: int64): int64 = a * b

con.registerScalar(multiply)

let r = con.execute("SELECT multiply(3::BIGINT, 7::BIGINT)")
echo r
┌──────────────────────────────────┐ │ multiply(CAST(3 AS BI.. │ ├──────────────────────────────────┤ │ 21 │ └──────────────────────────────────┘

A table function from a {.closure.} iterator

iterator fibonacci(n: int): tuple[i: int, fib: int] {.closure.} =
  var a, b = 0
  for idx in 0 ..< n:
    yield (idx, a)
    (a, b) = (b, a + b)

con.registerTableFunction(fibonacci)
let r = con.execute("SELECT * FROM fibonacci(8)")

See User-Defined Functions for aggregates, arrow function callbacks, named and cardinality hints.

Ship files straight to SQL

CSV, Parquet, JSON, Arrow — query them without import steps.

DuckDB's table functions read data files directly. NimDrake just hands the SQL to the engine: 

let r = con.execute("SELECT * FROM read_csv_auto('sales.csv')")
let p = con.execute("SELECT region, sum(amount) FROM read_parquet('q4.parquet') GROUP BY 1")
echo p

Installation

nimble install nimdrake

Distribution needs libduckdb.so / .dylib / .dll: the build looks in src/include/ (vendored via just fetch-lib) and then in the system via pkg-config / ldconfig.
